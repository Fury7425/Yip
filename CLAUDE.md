# Yip — Windows Audio Recorder

Minimalist Windows-only audio recorder. Native feel, absolute efficiency. No AI, no cloud, no telemetry.

## Stack (non-negotiable)

- **UI:** WinUI 3 + C++/WinRT, Windows App SDK `1.6.250108002`, CppWinRT `2.0.240405.15`, unpackaged & self-contained (`WindowsAppSDKSelfContained=true`)
- **Audio:** Rust staticlib (`audio_core.lib`) via FFI — WASAPI event-driven through `windows = 0.58`, `rtrb 0.3` SPSC ring, `hound 3.5` WAV writer, Windows Media Foundation (sink writer, OS-bundled encoders) for FLAC / MP3 / M4A, `parking_lot` for non-audio paths
- **VST3:** removed for now (see M5/M6) — the `vst-host` lib, `ProcessDialog` and `VstInterop` live in git history
- **Build:** CMake 3.27+ top-level → cargo (audio-core) + MSBuild (yip-app.vcxproj)
- **Toolchain:** VS 2022 (`v143`), Rust stable ≥ `1.85` (workspace pins it; edition 2024 requires it), Windows SDK 10.0.22621+, min platform `10.0.19041.0`
- **Target:** Win11 x64 primary, ARM64 secondary (`release-arm64` preset). No x86, no UWP.

## Architecture Rules (immutable)

1. Audio thread = zero alloc, lock, block, log. SPSC ring + atomics only.
2. Layer separation: UI → C ABI → Rust → WASAPI. No shortcuts. No C++ types cross FFI.
3. Threading: capture (Rust MMCSS Pro Audio), writer (Rust), UI (C++/WinRT).
4. Native only — no JS/webview/Electron.
5. No GC in realtime path.
6. No network in v1.

## FFI surfaces

Rust → C++ goes through a plain C header. No C++ types, no exceptions cross the boundary.

- **`audio_core.h`** — generated by `cbindgen` on every `cargo build`. Exports `rec_start / rec_stop / rec_pause / rec_resume / rec_is_paused / rec_meter / rec_peak_level / rec_reset_clip / rec_is_recording / rec_elapsed_ms / rec_current_path / rec_list_devices / rec_free_devices / rec_last_error / rec_set_state_callback`. `rec_set_state_callback` is the push channel that replaced the UI's idle poll timers; C++ fans it out via `RecordingStateBus`. **Pause is deliberately not on that channel** — a held take has not ended, so `rec_is_recording` stays 1 and the indicator stays on screen; the UI learns about it from `RecMeter::paused` on its next tick. `rec_pause` leaves the WASAPI stream running and discards packets in the capture loop, so resuming costs no re-initialise and the device never backs up; `rec_elapsed_ms` freezes for the held span. Status returned via `RecStatus` enum (0 = ok). Errors stored thread-local, read via `rec_last_error()`.
- **Output formats.** `RecConfig` carries `format` (`RecFormat`: WAV / FLAC / MP3 / M4A), `bit_depth` (WAV 16/24/32-float, FLAC 16/24) and `bitrate_kbps` (MP3, M4A). `format::Encoding::from_config` validates them before any thread starts. WAV goes through `hound`; the rest through `mf::MfSink` on the writer thread (float → 16/24-bit PCM, TPDF dither at 16 bits). MP3/M4A only take 44.1/48 kHz, so capture asks WASAPI for 48 kHz otherwise; encoded formats cap at stereo. The writer opens its file/encoder and reports back before `rec_start` returns, so a refused format fails at start (`RecStatus::Encoder`), never at stop. `yip-app` delay-loads `mfplat/mfreadwrite/mf.dll` (absent on Windows N/KN) and `mf.rs` probes for them first — keep both halves of that. App-side constants and labels live in [yip-app/RecordingFormat.h](yip-app/RecordingFormat.h).
- **Meter reads are lock-free.** `rec_meter` fills a `RecMeter` (peak envelope, smoothed RMS, session peak, clip count, overrun count, paused flag, dropped frames, frames captured, elapsed ms) from the process-wide `ring::METER` static, which the capture thread is the sole writer of. `rec_peak_level`, `rec_is_recording` and `rec_elapsed_ms` are plain atomic reads too — none of them take the recorder mutex, and none of them drain state, so both windows can poll at their own rate. Prefer `rec_meter` in new UI code: one call per tick instead of four.
- All Rust `extern "C"` lives in `ffi.rs`. Every entry wraps `catch_unwind` + null-check + UTF-8 validation. No other module exposes `pub extern "C"`.

## Design tokens

Every colour lives in [yip-app/App.xaml](yip-app/App.xaml)'s `Light` / `Dark`
theme dictionaries. **No colour is written in C++.**

- XAML reads them with `{ThemeResource ...}`.
- Code reads them through [yip-app/ThemeColors.h](yip-app/ThemeColors.h):
  `yip::theme::Brush(key)` for a XAML brush, `yip::theme::Color(key, fallback)`
  when Composition needs a `Color` rather than a `Brush`, and
  `yip::theme::SampleMeterRamp(n)` to sample `YipMeterGradientBrush` so the
  waveform and the XAML meter cannot drift apart.
- Composition holds copies, not bindings, so anything built from
  `yip::theme::Color` re-resolves on `ActualThemeChanged` (see
  `MainWindow::ResolveThemeBrushes` and `IndicatorWindow::ResolveThemeBrushes`).
  Brush objects are mutated in place rather than replaced, so every visual
  already holding one repaints untouched.
- The fallback colour in each file is a flat grey on purpose: if it ever
  appears on screen, a token key is wrong.
- Surfaces are a **tint over the window backdrop**, never an opaque fill. If a
  surface needs a solid colour to look right, Mica/acrylic has stopped working.
  The pill is the one exception: DWM draws a system backdrop over the whole
  window rectangle and ignores the window region, so behind a capsule acrylic
  leaked out as light corners. The pill's backdrop is the shell's host
  backdrop (already blurred) cut to the capsule by a D2D alpha-mask effect,
  under a lighter `YipIndicatorSurfaceBlurredBrush` tint. The mask mirrors the
  pill's opacity, scale and morph clip on the system compositor. With
  transparency effects off it falls back to a transparent backdrop and the
  denser `YipIndicatorSurfaceBrush`.
- Geometry and motion constants that only code consumes are **not** mirrored in
  App.xaml — the pill's state sizes and timings are `constexpr` in
  [yip-app/IndicatorWindow.xaml.cpp](yip-app/IndicatorWindow.xaml.cpp). Only
  what XAML binds to lives in the dictionary.

## Coding Conventions

### Rust
- 2024 edition, `#![warn(clippy::pedantic)]` with a vetted exemption list in [audio-core/src/lib.rs](audio-core/src/lib.rs) — extend only with justification.
- Custom `YipError` enum on public surface. No `anyhow` in public API.
- No `unwrap()` outside tests.
- No `unsafe` outside `ffi`/WASAPI/Media Foundation (`mf.rs`); every block needs `// SAFETY:` comment.
- `#[repr(C)]` on FFI types; opaque handles via `*mut c_void`.
- `#[unsafe(no_mangle)]` (2024 syntax), not bare `#[no_mangle]`.

### C++
- C++20 (`stdcpp20`), `/W4 /permissive- /Zc:__cplusplus`, `winrt::` namespace explicit.
- Smart pointers only (`winrt::com_ptr`, `std::unique_ptr`). No raw `new`/`delete`.
- `co_await` for async; no `.get()` on UI thread.
- PCH (`pch.h`) is mandatory for `yip-app/`.

### Naming
- Rust crates: `kebab-case` (`audio-core`)
- Rust mods/fns: `snake_case`
- C++ types: `PascalCase`, methods: `camelCase`, namespace: `yip::`
- XAML: `PascalCase` elements, `x:Name` in `PascalCase`. Each `.xaml` has a matching `.idl` for codegen.

## Anti-patterns

- ❌ Allocation in audio capture callback
- ❌ `Mutex`/`RwLock` on the audio→writer hot path (the only `parking_lot::Mutex` allowed is the FFI singleton guard, never touched from the capture thread)
- ❌ `println!`/`OutputDebugString` from audio thread
- ❌ Hardcoded paths/rates/devices
- ❌ A colour literal in C++ — resolve it from App.xaml via `yip::theme`
- ❌ TODO/FIXME without matching milestone box
- ❌ Suppressed warnings to ship (`-D warnings` in clippy, `/W4` in MSVC)
- ❌ Mixing `Result` + exceptions across FFI
- ❌ C++ types in `audio_core.h`
- ❌ Editing `audio-core/include/audio_core.h` by hand — regen via `cargo build`

## Build Verification

```powershell
# Rust gate
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --release

# Native gate
cmake --preset release
cmake --build --preset release

# ARM64 cross-build gate
cmake --preset release-arm64
cmake --build --preset release-arm64

# C++ format (informational — CI uses continue-on-error until first sweep flips green)
clang-format --dry-run -Werror --style=file (Get-ChildItem -Recurse -Include *.cpp,*.h -Path yip-app).FullName
```

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) runs three jobs on `windows-latest`: `rust` → `native` (depends on rust) → `format-cpp` (continue-on-error). All required gates green before milestone advance.

Output binary: `build/release/yip-app/Release/yip-app.exe` (self-contained, no Windows App SDK install required).

## Milestones

- **M1–M3** ✅ — Rust FFI skeleton, WASAPI capture + WAV writer, MainWindow + device picker + start/stop.
- **M4** ✅ — Recording indicator pill (Composition state machine, GPU meter, click-through; idle/armed hidden by product decision). The pill's "Mark moment" and "Open last" buttons were removed by product decision — expanded it offers Pause and Stop, in that order (the recoverable action takes the inner slot). `Markers.cpp` stays: deleting a take still removes any existing sidecar. The pill is fixed, centred at the top or bottom of the primary display's work area (`pill_bottom` in `settings.json`) — it cannot be dragged, and neither drag nor edge-dock state is persisted (`indicator.json` keeps only the click-through and last-expanded flags). `pill_dot` shrinks the collapsed pill to a 24 DIP disc holding just the recording light; a tap still expands it to the full readout and controls. Both settings reach the pill live through `Settings::SetSavedHandler`. **The HWND is sized once per show, for the expanded state, and never resized while on screen** — resizing it per state could not be made seamless (DWM moves the window a frame or more before the island redraws, so the old capsule flashed out of place on every expand/collapse). The Border changes size inside it, layout keeps it centred and flush with the anchored edge, a composition clip morphs between sizes, and a rectangular window region keeps the transparent margin from swallowing clicks.
- **M5/M6** ⏸ — **VST3 support removed for now.** It existed as a `vst-host` static lib (C ABI `yip_vst_load / unload / param_count / param_at / render / last_error`, SDK-gated via `YIP_HAVE_VST3_SDK`, passthrough render without the SDK) plus a Process dialog (`ProcessDialog`, `VstInterop`, title-bar button, Ctrl+P). Never did real Steinberg processing and read whole takes into RAM. Restore from git history if it comes back.
- **M7** ⏳ — Done: global start/stop hotkey (`HotkeyManager`, Ctrl+Alt+R, persisted) **and** its config UI (capture box in `SettingsDialog`, validated + persisted); idle-CPU 0% (`rec_set_state_callback` → `RecordingStateBus` → per-window meter timers, no timer ticks while idle); ARM64 CI (`native-arm64` job, CMake now passes `--target` to cargo); installer ([installer/yip.iss](installer/yip.iss), Inno Setup, per-user, self-contained); lock-free meter snapshot (`rec_meter`) plus the bulk-copy capture path and batched writer drains; main-window redesign (Mica, extended title bar, elapsed clock, logarithmic meter with peak-hold and clip lamp, filterable recordings list with a context menu, `InfoBar` error surface, keyboard accelerators) and the design-token layer in [yip-app/App.xaml](yip-app/App.xaml); notification-area icon ([yip-app/TrayIcon.cpp](yip-app/TrayIcon.cpp) — hidden top-level host window so `TaskbarCreated` re-adds after an explorer restart, no `guidItem` so a moved exe still registers, failed `NIM_ADD` retried for ~20s, glyph driven off `RecordingStateBus`) and recording formats (WAV 16/24/32-float, FLAC 16/24, MP3 128–320 kbps, M4A 96–192 kbps via Media Foundation; Settings picker, recordings list probes non-WAV through the shell property store; and single-instance ([yip-app/SingleInstance.cpp](yip-app/SingleInstance.cpp) — session-local named mutex claimed in `wWinMain`; the loser posts a registered message to the winner's tray host and exits). **Window lifetime belongs with the tray icon:** closing the main window hides it (`App::WireCloseToTray` → `AppWindow.Hide()`) instead of ending the session, so capture and the hotkey carry on and the icon — or relaunching the exe — brings the window back. `App::Quit` is the only real exit (tray menu, or a close while no icon is registered): it stops any take, drops the icon, closes both windows and calls `Application::Exit()`. Not optional tidiness — the XAML application does **not** end when MainWindow closes, so before this the process lived on with no window and no icon, unreachable, and the next launch found the mutex held and quietly did nothing.
